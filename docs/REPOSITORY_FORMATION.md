# 仓库形成与接纳记录

状态：Candidate decision，待 Owner 确认；事实核验日期：2026-09-20。拟议 verdict：`REPO_NOW_PUBLIC`。仓库已由 Owner 建立为 Public，不将建仓事实解释为实现开工、独立复用或 Authority Admission 已完成。

## 1. 责任与拆分理由

主责任：独立、持久的数字制品记录。仓库名称 `infra-artifact-ledger` 表达基础组件类别及长期责任，不绑定 Python、SQLite、某个 Agent 或云供应商。

| 形成问题 | 本仓答案与证据边界 |
|---|---|
| A1 主责任 | 制品身份、版本、内容绑定、来源记录与幂等成功结果；不随上层业务更换而消失 |
| A2 负边界 | 不拥有证据/知识准入、权限、模型调用或工作流编排 |
| A3 变化原因 | 持久记录的正确性、兼容性与存储实现；业务提示词和消费者流程不进入本仓 |
| A4 独立闭环 | A1 计划提供无宿主的库/CLI 操作、读回与迁移验证；当前尚无执行证据 |
| A5 接口边界 | 本仓公共接口提案固定字段和行为；Candidate，尚非稳定发布 |
| A6 权威完整性 | 同一 Ledger 的记录、bytes 和成功结果由一个事务边界管理，无两个独立写入真相 |
| A7 依赖方向 | 消费者 → 公共接口 → backend；核心不反向依赖具体消费者 |
| A8 生命周期 | 独立包版本、兼容格式、许可与维护；业务应用可独立升级，尚待实际采用验证 |

元数据、payload 与幂等结果不再物理拆成不同仓库；此处跨越原子不变量的拆分收益不足。版本/来源、证据、知识虽可引用彼此，生命周期与准入决定仍由各自所有者维护。

复用评估为 **E2 的结构性候选**：责任稳定且能脱离具体消费者表达。当前已集成消费者为 **0**，不存在 E3 的真实复用证明。Code Driver consumer 和独立 Generic Agent consumer 是计划对象，不能用两个示例脚本或仓库数量代替证据。

## 2. 收益、成本与否决条件

独立发布预计能使个人、团队与外部项目采用同一制品格式，避免与特定产品一同升级。成本是额外版本管理、接口兼容检查、跨仓问题定位和维护工作。首次交付仅一个包、一个 backend、一套公共语义，不提前拆适配器或创建空仓。

| 风险检查 | 设计结果 / 待验证 |
|---|---|
| V1 权威混淆 | Ledger 不替消费者作业务准入；只有一种记录权威 |
| V2 共享可变状态 | 消费者经 API 写入，不直接修改 SQLite 表 |
| V3 向上依赖 | 公共使用无需私有宿主；A1 隔离安装将验证 |
| V4 跨仓原子性 | bytes/metadata/幂等均在本组件同一事务；不要求跨知识库事务 |
| V5 长期锁步 | 目前没有实际发布证据；A3 后检查是否每次改动都被迫同步消费者 |
| V6 按部署拓扑拆仓 | 一个 backend 留在本仓；不按本地/云或流水线节点数机械拆分 |

若真实采用显示长期只有宿主私有逻辑、频繁锁步、重复真相或合同无法独立测试，应重新评估模块边界和是否保持独立仓库。若资源上限和完整历史导入不适合消费者，先调整明确版本的合同，不静默扩大首版。

## 3. Public 采用与许可

公开范围是本组件独立工程文档、后续代码、合成示例和符合性测试；不包含私有推导正文、聊天记录、真实用户内容或内部配置。公共接口保留必要的格式兼容标记，字段完整说明在本仓，不以私有来源链接替代实现规格。

Clean-room adoption 当前是待验证目标：没有安装包、可运行示例或真实外部使用证据，因此不声明 PASS。MIT 许可方案已随 A1 开工决定获 Owner 确认；P1 加入 LICENSE 后才形成相应许可交付。公共用户不需要私有维护规则即可理解软件合同；维护执行者读取规则的要求见 [Gate](PROGRAM_REPOSITORY_DOCUMENTATION_GATE.md)。

## 4. Git 与存储接纳状态

| 角色/检查 | 当前事实 |
|---|---|
| GitHub Publication / Collaboration | Public 仓库已创建；初始提交 `e26a9d6a524a8f0c0ab50b56cb8f03c61d12c23a` |
| 本次工作副本 | 文档编辑与提交暂存；不作为权威迁移证据 |
| NAS Git Authority | 尚未接纳；无目标 refs/HEAD 对齐、server fsck 或切换证据 |
| Backup Authority | 尚未记录独立备份与恢复证据 |
| Runtime 数据恢复 | A2 后续范围；与 Git Authority 接纳分开 |

拟议 Git Authority 目标使用逻辑服务身份 `ssh://git-authority/repos/infra-artifact-ledger.git`；它不是已连接的真实地址。接纳前确认全量 heads/tags、HEAD、对象完整性、目标命名冲突与备份；先 dry-run，再核对迁移后 refs 与服务端完整性，并保存配置/恢复证据。不能只用 main SHA 相等作完成证明；零 tag 合法但须明确检查。

接纳完成后才配置 `origin` 指向 Git Authority、`github` 指向 GitHub 协作端。当前未执行该切换，也不把 GitHub 暂存来源自动宣布为 NAS 权威。不得覆盖、重建或强推未知目标。维护者遵循固定的私有形成规范来源 `kongbu0621/engineering-sop@91ac1ad72a423079785725fafd4eb139f5cd7943`，路径 `docs/principles/repository-formation-standard-v1.0.md`；本文件仅记录本项目判断与事实。
