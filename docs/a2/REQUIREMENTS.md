# A2 需求：一致快照、NAS 保存与新目标恢复

状态：**Candidate，待 Owner 审查；A2 Gate OPEN**。Decision Authority：Owner。提议范围：`A2-snapshot-nas-restore-v0.1`。输入实现基线：`bd5128e7cebc844d8fca622c791681f7c65184f8`；当前软件仍为 A1 `0.1.0a1`。本提案不修改已批准 A1 语义，授权见 [A2 Gate](GATE.md)。

## 1. 为什么做、为谁做

A1 已能独立安装、保存制品、读回与校验，但本地唯一数据库丢失时，还没有经过真实 NAS 恢复验收的路径。A2 为个人、团队和外部应用增加可独立使用的备份/恢复能力，给未来本地知识库提供可恢复的制品底座。

核心场景：GX10 在本机可靠文件系统运行 Ledger；取得一致快照并保存到已确认的 NAS 挂载存储；本地验收副本丢失后，从 NAS 恢复到全新本地目录，原有身份、版本、字节、来源与成功幂等结果仍一致。每台机器、每个项目独立 venv，项目、环境和数据分开；路径由部署侧提供。

恢复保留原状态，不执行 A1 import，不新增 ImportReceipt 或成功写入记录。snapshot_id 只标识本次备份，不取代 Artifact/Version 身份，也不成为知识准入决定。

## 2. 需求与失败信号

| ID | 必须满足的行为 | 失败信号 |
|---|---|---|
| A2-R01 | 在明确的一致读取状态上产生本地 SQLite 快照；失败不改源 | 复制活跃文件、混合不同提交、包含未提交内容 |
| A2-R02 | 独立快照格式、身份、固定成员和精确字节摘要 | 将 SQLite 文件称为 portable 包，或只看目录存在就认定完成 |
| A2-R03 | 真实存储发布前后核对挂载身份，最后发布完成标记并回读 | NAS 未挂载而写进本机目录；中断仍报告完成 |
| A2-R04 | 独立核对摘要、数据库结构/外键、Ledger 语义和全部 Blob | 只验 JSON/计数/大小；损坏后继续恢复 |
| A2-R05 | 只恢复到原子独占的新目录，保留 records/operations/refs/payload | 覆盖已有目标、丢失幂等历史、改 ID 或增加业务记录 |
| A2-R06 | 区分未发布、已发布和结果不明；可按原身份/摘要核对 | I/O 异常一律解释为未发布；以覆盖重试消除不确定 |
| A2-R07 | 明确资源预算、检查点超时和清理规则 | 一次加载整库 Blob、无限重试、误删已有数据 |
| A2-R08 | 库与 CLI 独立复用，A1 行为保持 | 依赖私有仓库、厂商 SDK、账号或固定本机路径 |
| A2-R09 | 真实 NAS 演练只操作独立合成数据，全量对账并留证 | 本地目录冒充 NAS；删除真实库；摘要被当作来源认证 |

## 3. 范围与限制

交付本地 SQLite 快照、校验、挂载存储保存、拒覆盖恢复、恢复结果核对和隔离安装/故障/真实 NAS 验收。字段与预算以 [接口提案](INTERFACE_PROFILE.md) 为准。

首版支持 A1 schema 1、`bounded-local-v0.1`、DELETE journal且数据库编码为UTF-8；其他编码明确拒绝，不转换。这是A2的支持子集，不收紧A1自身接口。源和恢复后的运行库在本机可靠文件系统；NAS 只保存关闭后的静态快照。允许短暂延迟源写提交，不承诺无停顿在线备份；本地 backup 完成即释放源读锁，NAS 传输不占源数据库事务。

不含自动调度/常驻服务、NAS 挂载/凭据管理、自动删除/轮换、增量同步、加密/签名服务、WAL、跨 schema 迁移、任意云适配、第二数据库实现、知识审核或跨库联合恢复。Local Hand 接纳、NAS Git Authority、A3/A4 分别留证，不计入 A2 完成。

公开仓库只保存通用文档、代码、合成测试和脱敏结果。真实 mount source、共享路径、凭据和 payload 留在部署侧。调用方独立保存预期 manifest 摘要；不能把归档里的自报摘要当身份认证。

## 4. 完成定义

完成 [实施计划](IMPLEMENTATION_PLAN.md) S1–S5 与 [验收矩阵](ACCEPTANCE.md)，并同时满足：

1. Linux/Python 3.11 必验；GX10 ARM64/Python 3.12.3 实际组合另验；A1 全套必需回归通过。
2. 一致性、拒覆盖、损坏、失败位置和响应丢失都有检查实际副作用的正反例；未运行项明确标记。
3. 真实 NAS 保存后，移除隔离验收中的本地数据库、快照及临时可恢复副本，仅从 NAS 恢复；对独立小型预期清单和全部内容进行核对。
4. 恢复后原请求重放返回原结果且记录数不变；另在测试副本执行新写入。
5. 记录源提交、wheel 摘要、解释器、SQLite、storage profile、命令、退出码和结果。进程中断或回读不冒充真实断电耐久证明。

## 5. 候选约束与待验证条件

首版建议 1 GiB 数据库预算与独立 metadata/索引预算，支持超过 portable 上限的累计内容并限制验证内存。限额随本提案一起审查和实测；超限拒绝，不截断。这不限制 A1 累计库大小，也不保证所有 A1 合法大库都能由首版 A2 备份。

NAS 协议、挂载参数和必要能力尚未采集，按 [验收前置](ACCEPTANCE.md) 验证。能力不满足则停止该目标验收、修订适配方案，不静默降低保证。本地功能、文件系统能力、真实 NAS 闭环分别记录。
